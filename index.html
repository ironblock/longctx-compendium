2 · Ceilings one model, one depth · what physics allows before any software

Decode (one stream, one token per pass) is bounded by memory bandwidth ÷ the bytes each step must read: the active weights, the whole KV cache of every full-attention layer, the window of every sliding-window layer, and the state of every linear-attention layer. That grows with depth at a rate set by the model's architecture — which is why a hybrid model and a dense one cannot be compared on raw tokens/sec, only each against its own ceiling. Prefill is bounded by rated matrix throughput at the precision the engine actually multiplies in; real prefill lands far below it, so read it as a bound, not a forecast.

Method & sources

  • Format support is recorded once per chip generation in data/compendium.json → architectures, each with the sources it rests on. “Native” means the matrix units take that input type; emulating it or upcasting to a wider type does not count. A card can override its generation only with a note saying why. FP8 weights can still be stored on a card without FP8 matrix units — that saves memory and bandwidth, not compute. Apple publishes no list of the types its GPUs multiply natively. M3 and M4 read “absent” because Apple says GPUs before M5 have no neural accelerators and fall back to shader code; M5 reads “native” for FP16 and INT8 on Apple's own example and an independent benchmark, and “unknown” for most of the rest.
  • Decode ceiling = bandwidth ÷ (weights read × bits per weight ÷ 8 + KV bytes at depth + recurrent state). Weights read = active parameters less an untied input embedding table, of which a step reads one row; a tied table doubles as the output head and is read in full. KV bytes = 2 × KV heads × head size × bytes per element, for every full-attention layer times the depth and every sliding-window layer times its window; an MLA model stores one compressed latent per position instead, and a block-sparse layer reads only its fixed budget of positions however deep the cache. Recurrent state is one key×value matrix per head per linear-attention layer at FP32. Under a layer split a single stream runs one card at a time, so it gets one card's bandwidth; under tensor parallel it gets all of them, with perfect scaling assumed.
  • Prefill ceiling = rated dense matrix throughput ÷ FLOPs per token, where FLOPs per token = 2 × active parameters + 4 × attention heads × head size × positions attended on each softmax layer (a cold prompt attends over half itself on average). Every card counts under either split. The precision is the one the engine actually multiplies in: GGUF quants follow llama.cpp's own kernel dispatch (docs/roofline-dequant-paths.md), FP8 checkpoints use FP8 only where the matrix units take it, and anything ungrounded falls back to FP16 and says so. Datacenter Blackwell (B200, B300) takes llama.cpp's Hopper paths, because its Blackwell-specific kernels target the workstation chips only. A card with no matrix units at all is bounded by its fastest shader rate (packed FP16 or dot-product INT8), labelled “vector”. Where a vendor never published a rate for a card, one worked out from its other ratings or taken from a third party stands in, labelled “unofficial”, with the working in the card's note.
  • Fit = all parameters × bits per weight + KV at depth + recurrent state, against every card's memory less 1 GiB each for the runtime. Catalog memory is read as GiB, which is what vendors mean. Under tensor parallel, a model with fewer KV heads than cards replicates them, and an MLA model's latent cache is copied whole to every card; the table warns when a model's attention heads do not split evenly across the cards. Unified-memory machines give the GPU only part of their RAM by default; that is in each unit's note, not the arithmetic.
  • What the ceilings leave out on purpose: kernel launch and synchronization cost, MoE routing, batching, interconnect time under tensor parallel, and any precision mix within a checkpoint (gpt-oss keeps attention in BF16, so its true ceiling is lower than one computed at MXFP4 throughout). Each omission makes the ceiling higher, never lower, so it stays an upper bound.
  • Model shapes are transcribed from each model's published config.json and model card, with the URL beside each entry in assets/models.js. Bits per weight for GGUF recipes (Q4_K_M and similar) are typical averages; a line that records its own measured width uses that instead.
  • Observations keep the source's own words where it gave a range, a caveat or no depth. “Recorded” is when a figure entered this page, which is the latest it could have been observed; “observed” is the source's own date where it gave one. Witnessed means the maintainer personally saw the hardware produce the numbers; reported is someone else's account, kept because nothing gives a specific reason to doubt it. A line whose source names only the model's size gets a weights-only bound, which leaves out the cache and so sits above the true ceiling. A withdrawn line stays visible with the reason it was withdrawn.
  • Editing: every number lives in data/compendium.json; data/README.md says how to add a card, a chip generation or a reading, and tools/check-ceilings.mjs fails if any reading claims more than its hardware can do.
